# GitHub README 格式规范

这是从 `topsun-bot/Robot-Brain` README 提炼出的 GitHub 项目页格式。它解决的是信息层次、视觉入口、证据边界和渲染检查，不替代项目自己的技术文档。

## 适用范围

- 项目仓库的根目录 `README.md`。
- 组织主页或项目集合页中的重点项目展示区。
- 需要在 GitHub 页面上同时服务访客、开发者和维护者的项目。

仓库之间只复用共同结构；项目名称、能力描述、命令、图片、证据和链接必须来自当前仓库。不同技术栈仍需保留自己的安装、测试和发布说明。

## 推荐结构

1. **一级标题**：项目名称，保证独立阅读和无障碍结构完整。
2. **Hero 区**：可选的本地 SVG／图片、价值主张和少量事实型徽章。
3. **页面导航**：指向 README 内部稳定入口，使用短锚点。
4. **真实演示**：先展示可观察结果，再说明能力；图片、GIF、视频链接必须有替代文本或文字说明。
5. **能力地图**：按用户能理解的任务或能力分组，链接到实际代码和文档。
6. **工作机制**：用一张流程图或简短步骤解释输入、执行、反馈和证据。
7. **证据与边界**：给出日期、样本、指标、方法和未覆盖范围；模拟、离线和真机结果分开写。
8. **快速开始**：提供最短可运行路径，代码块标注语言，并注明硬件、密钥和模型依赖。
9. **深入文档**：按系统、硬件、开发、验证分组，避免堆积无分类链接。

## GitHub 渲染约定

- 可以使用 HTML 表格、`<details>` 和图片布局来实现 GitHub 展示页，但这属于 GitHub 优化格式，不保证所有 Markdown 渲染器等价显示。
- 保留 Markdown 一级标题；如果 Hero 图片内部已经包含项目名称，应在设计阶段决定是否接受标题重复，不能为了视觉隐藏标题而牺牲文档结构。
- 图片和 GIF 使用仓库内相对路径；每张图片写清楚 `alt` 文本。
- 代码块必须写语言标识，例如 ` ```bash `。
- 源文件保留 EOF 换行；长段落按语义拆行，方便审阅和变更。
- 显式锚点只保留实际被导航或外部链接使用的稳定入口；章节标题本身仍使用正常 Markdown 标题。

## 内容边界

- “已实现”“已验证”“演示过”“计划支持”分开表述。
- 论文、离线评测、仿真和真机验收分别标注，不能用一个数字覆盖不同实验条件。
- 外部仓库、设备网关和云服务写明职责边界；链接失效或需要组织权限时要说明。
- README 只做入口和定位；完整 API、部署、故障恢复和开发约定放到 `docs/` 或项目维护文档。

## 验收清单

- [ ] 首行是一级标题，章节层级连续。
- [ ] Hero、徽章、图片和 GIF 在 GitHub 页面加载正常。
- [ ] 所有本地链接和图片路径存在，内部锚点可以跳转。
- [ ] 快速开始命令来自当前仓库，并注明前置条件。
- [ ] 评测数据包含日期、样本、方法和限制。
- [ ] README 在窄屏下仍可阅读；表格没有承载无法替代的关键信息。
- [ ] lint 规则明确允许的 GitHub 专用 HTML，不把 0 lint 当作渲染通过的唯一证据。
